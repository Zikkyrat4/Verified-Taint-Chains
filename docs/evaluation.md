# Оценка VTC — финальные результаты

> **Финальная версия для диплома.** Прогон на модели **qwen-coder:30b**
> (локальная Ollama), детерминизм через `OLLAMA_SEED`. Набор фикстур — 5
> реальных проектов, 5 классов CWE. Эталоны `ground_truth.json` детектор
> **не видит**: они подаются только в `scripts/evaluate.py` для подсчёта
> метрик *после* прогона пайплайна.

## Агрегированные метрики

| Project | TP | FP | FN | Uncl | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| jenkins-docker-commons | 1 | 0 | 0 | 1 | 100.00% | 100.00% | 1.0000 |
| jenkins-perfecto | 0 | 0 | 1 | 13 | 0.00% | 0.00% | 0.0000 |
| jspwiki | 2 | 2 | 0 | 1 | 50.00% | 100.00% | 0.6667 |
| keycloak | 6 | 15 | 2 | 199 | 28.57% | 75.00% | 0.4138 |
| webgoat (project-mode) | 1 | 7 | 2 | 2 | 12.50% | 33.33% | 0.1818 |
| **TOTAL** | **10** | **24** | **5** | **216** | **29.41%** | **66.67%** | **0.4082** |

`Precision = TP / (TP+FP)`, `Recall = TP / (TP+FN)`, `Unclassified` —
цепочки, не совпавшие ни с TP, ни с известным FP-паттерном (кандидаты в
0-day / материал для триажа), в precision/recall не входят.

## Как читать это число (методология защиты)

VTC спроектирован как инструмент поиска **неизвестных (0-day)** уязвимостей,
поэтому метрики интерпретируются под эту цель, а не максимизируются под
бенчмарк.

1. **Recall важнее F1.** При сознательном отказе от жёстких keyword-фильтров
   (см. ниже) инструмент видит большинство реальных уязвимостей — recall 67%,
   включая кросс-файловые потоки и 5 разных классов CWE. Для 0-day цена
   пропуска (FN) выше цены ложной тревоги (FP).
2. **Низкая precision (29%) — это дизайн, а не дефект.** Подозрительные
   потоки выносятся в FP/Unclassified для человеческого триажа, а не
   отбрасываются молча. Большинство FP — это контекстно-безопасные
   framework-значения (`state`, `relayState`, `samlRequest`, `clientSession`),
   которые универсальный детектор **обязан** флагать: они attacker-influenced,
   и подавление их ради метрики ослепило бы инструмент на 0-day с такими же
   паттернами. Мы сознательно их **не** подавляли.
3. **Никакой подгонки под тесты.** Эталоны описывают *истинный* сток, а не то,
   что удобно засчитать. Пример: jenkins-perfecto TP-1 размечен на
   `cmdArgs` (аргумент `Runtime.exec`) — детектор сейчас терминирует цепочку
   на промежуточной командной строке `baseCommand`, поэтому кейс остаётся
   честным FN, а не натянутым TP.

## Где сейчас бутылочное горлышко

Все 5 остаточных FN — одной природы: **recall этапа Stage 1** (извлечение
спецификаций LLM). Модель не выделяет нужную пару source/sink:

| FN | Граф потоков (Stage 2-4) | Чего не хватает от Stage 1 |
|---|---|---|
| webgoat TP-3 (`id→catPicture`) | ✅ ребро строится | source `id` + sink `catPicture` |
| webgoat TP-4 (`e→f`) | ✅ ребро строится | source `e` + sink `f` |
| jenkins-perfecto (`→cmdArgs`) | ✅ ребро строится | пометка exec-аргумента стоком |
| keycloak Serialized (`value→clazz`) | ✅ ребро строится | стабильная пометка пары |
| keycloak SamlService | — | целевой поток тонет в 204 цепочках XML-десериализации |

То, что Stage 2/3/4 и кросс-файловые мосты корректно строят все эти потоки,
подтверждено детерминированными unit-тестами (без LLM). Узкое место — recall
LLM-извлечения, и это честное ограничение signature-guided подхода, а не
ошибка пайплайна.

## Универсальность контракта

Ядро (`src/`) остаётся project-agnostic. Инвариант (должен быть пуст):

```bash
grep -rinE "keycloak|authSession|getAuthNote|AuthenticationFlow" src/ --include="*.py"
```

Специфика проектов живёт только в `tests/fixtures/real_world/<project>/`.
Добавление проекта = новая директория, без изменений ядра.

## Универсальные правки ядра в этой итерации

Все — исправления корректности, помогающие 0-day на реальном коде; ни одна не
кодирует знание о фикстурах:

1. **Byte-offset в `_get_node_text`** (`src/stage1_llm_inference/ast_parser.py`).
   tree-sitter отдаёт смещения в **байтах** UTF-8; срез по индексам `str`
   сдвигал все идентификаторы после первого не-ASCII байта (`©` в
   лицензионном заголовке → `catPicture` превращался в `atPicture`), из-за
   чего рёбра потоков молча терялись на **любом** реальном файле с не-ASCII
   заголовком. Самая важная правка для применимости на практике.
2. **Парсинг array-литералов** `Type name[] = {...}` в data-flow экстракторах —
   обычный синтаксис Java, рёбра в массив больше не теряются.
3. **Parameter pass-through мост** (`_build_scoped_graph`): источник `var` в
   файле A соединяется с одноимённым параметром в файле B, который течёт
   дальше — приближение межпроцедурного потока для наследования/делегирования
   (подкласс → метод базового класса). Даёт webgoat TP-1 кросс-файлово.
   Generalizуется на любой OOP-код.
4. **Исправления ground truth** (не детектора): keycloak `ctxData→deserialized`
   (переменной `ctxData` в коде нет); webgoat single-file стоки на
   File-объект, построенный из заражённого пути (`catPicture`/`f`) — истинный
   path-traversal сток, а не self-loop `source==sink`.

## Воспроизведение

```bash
# Локальная Ollama с qwen-coder:30b, детерминизм:
export LLM_PROVIDER=ollama LLM_MODEL=qwen-coder:30b OLLAMA_SEED=42

python scripts/evaluate.py --all-projects --save final   # все проекты + агрегат
python scripts/evaluate.py --project webgoat --save final # один проект (project-mode)
```
